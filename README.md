# 📊 Customer Churn Prediction

A Machine Learning project that predicts whether a customer is likely to **churn (leave a service)** or **stay**.

This project uses a **Random Forest Classifier** trained on customer demographic, service, contract, and billing information. The model also uses a custom prediction threshold of **0.35** to increase the ability to identify customers who are likely to churn.

## 🔄 Data Preprocessing

### 1. Remove Customer ID

The `customerID` column is removed because it is an identifier and is not useful for predicting churn.

```python
df.drop('customerID', axis='columns', inplace=True)
```

### 2. Convert Total Charges

Some `TotalCharges` values contain blank spaces, so they are removed before converting the column to numeric format.

```python
df1 = df[df.TotalCharges != ' ']

df1.TotalCharges = pd.to_numeric(df1.TotalCharges)
```

### 3. Convert Yes/No Values

Several categorical columns contain `Yes` and `No`.

They are converted into:

```text
Yes → 1
No  → 0
```

This allows the Machine Learning model to process them numerically.

### 4. Convert Gender

Gender is converted to numerical values:

```text
Female → 1
Male   → 0
```

### 5. One-Hot Encoding

Categorical columns such as:

* InternetService
* Contract
* PaymentMethod

are converted into numerical columns using Pandas `get_dummies()`.

```python
df2 = pd.get_dummies(
    data=df1,
    columns=['InternetService', 'Contract', 'PaymentMethod']
)
```

Boolean values generated by one-hot encoding are then converted to integers.

## 🌲 Random Forest Model

The project uses a Random Forest Classifier with:

```python
RandomForestClassifier(
    n_estimators=300,
    max_depth=12,
    min_samples_split=5,
    min_samples_leaf=2,
    class_weight='balanced',
    random_state=5,
    n_jobs=-1
)
```

### Important Parameters

| Parameter           |    Value | Purpose                           |
| ------------------- | -------: | --------------------------------- |
| `n_estimators`      |      300 | Number of decision trees          |
| `max_depth`         |       12 | Maximum depth of each tree        |
| `min_samples_split` |        5 | Minimum samples required to split |
| `min_samples_leaf`  |        2 | Minimum samples in a leaf         |
| `class_weight`      | balanced | Helps handle class imbalance      |
| `random_state`      |        5 | Makes results reproducible        |
| `n_jobs`            |       -1 | Uses available CPU cores          |

## 🎯 Custom Prediction Threshold

Instead of using the default probability threshold of `0.50`, this project uses:

```python
threshold = 0.35
```

The model first calculates the probability that a customer will churn:

```python
probabilities = random_forest.predict_proba(x_test)[:, 1]
```

Then:

```python
pred_rf = (probabilities >= threshold).astype(int)
```

This means:

```text
Probability >= 0.35 → Churn
Probability < 0.35  → Not Churn
```

Using a lower threshold can classify more customers as potential churners, which can increase **recall for the Churn = Yes class**.

## 💡 What is Customer Churn?

**Customer churn** means that a customer stops using or leaves a company's service.

For example, if a customer cancels their internet or telephone subscription, that customer has **churned**.

In this project:

```text
Churn = 1 → Customer Churned
Churn = 0 → Customer Stayed
```

---

## 🎯 Why Churn Recall Matters

Recall for `Churn = Yes` measures how many of the customers who actually churned were successfully identified by the model.

For example, if there are 100 customers who actually churned and the model correctly identifies 80 of them:

```text
Churn Recall = 80%
```

A higher recall means fewer actual churners are missed.

This is particularly useful when the business wants to identify customers who may leave and potentially take retention actions.
